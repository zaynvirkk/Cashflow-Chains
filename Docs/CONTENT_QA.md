# All-content preview for the developer

`PlayContentQA.sh` launches a **separate development build** with an isolated local save and a permanent CONTENT QA watermark. It lets the operator review all104 cities,32 buildings,16 combos, eight collections, neon/founder finishes and twelve blueprint slots without a real purchase.

The fixture computes reference results in the pure domain to prepare an all-content profile. These are **not human/ordinary-input progression or payment receipts**. It creates no store orders, purchase references, gems or draft tickets. No fake product price or store-success callback is used. The normal release build compiles out fixture creation, ignores the QA command, and rejects QA-marked saves. A regression explicitly launches the ordinary build with the QA argument and verifies zero stars/entitlements.

The developer test then uses ordinary controls to solve the final Finance city and a quota-limited Harbor city, returns through their district maps, checks all20 Finance buttons on portrait/wide layouts, applies the actual eight-sprite neon pack and founder finish, saves/loads an extra blueprint and claims a collection exactly once. The report clearly labels the fixture; it supplements the real72-city progression replay and never replaces real Google Play sandbox tests.

Do not distribute this development build as the production release or use its fixture completion totals as engagement/revenue evidence. The production archive contains only the regular player. The QA archive is separate and visibly labelled.

Build: `Tools/build.sh content-qa`. Test: `python3 Tools/content-qa-playtest.py`. Evidence marker: `Artifacts/latest-content-qa.txt` once passed. Regular game: `Play.sh`.
